# Lite visuals

`KNL_VISUALS=lite` reduces decoration. An unset value or `KNL_VISUALS=full` uses the existing rendering and particle dispatch. This setting does not alter simulation timestep, collision logic, AI, upgrades, saving, canvas UI, sprite animation, lighting, or resolution.

The lite water pass fills the same waterline-to-bottom region with an opaque, tinted depth gradient. It retains the original water tint and current ambient sky color, so weather and day/night lighting still affect it. Ripples and mirrored scenery/characters are removed. Backdrop gradients and point lighting remain enabled. Screenshot inspection found a complete, continuous water region with no blank strips; visual preference and other times of day still need device gameplay review.

Lite also reduces the named decorative `CloudController` budgets before their initial Awake can create pooled objects: CloudsCumulus 160 → 12, CloudsStratus 10 → 4, Fogs 30 → 0 and Mists 25 → 0. Authored smaller budgets are never increased. Unknown controllers and IceFloes retain their settings. Each controller still initializes its material and receives its original updates; world weather, wind, density, season and time are untouched. These changes take effect when the game starts; they do not attempt to remove clouds from an already running scene. Original method-body references outside Cloud/CloudController only access the debug fog switch or the initialized materials used by ShadowCamera, so retaining controller initialization matters. A compatibility-runtime dump after 2,400 frames confirmed both capped fog and mist pools were empty, with zero live fog/mist sprites.

The native worker recognizes an opaque, full-width vertical gradient that reaches the bottom of the framebuffer, such as lite water. It avoids rasterizing earlier sprite pixels that this fill will cover. The full sprite bounds return at the fill, so foreground and HUD drawing retain their order. Translucent, additive, partial-width or bounded gradients do not qualify. This optimization changes hidden work rather than final pixels.

Particle Playground remains initialized and callable. Lite bypasses its manager's expensive `LateUpdate` particle calculations only when there are no subscribed particle callbacks, serialized particle events, or consumers that track particles. The plugin clock still advances. A newly attached consumer restores ordinary particle dispatch on the next frame. Other lifecycle methods and emitter API calls remain intact. The compatibility renderer currently does not draw `ParticleSystemRenderer`, so this primarily avoids computing particles that were already invisible; it does not remove existing rendered fire sprites, selection UI, tutorial text, or weather gameplay controllers.

The original owned Assembly-CSharp.dll examined has SHA-256 `89e7bdc9b18ccb4a6d37e93c09245c58d67506d92d1fdc26206ef096c73150e3`. A full scan of method bodies outside the ParticlePlayground namespace found game callers only emitting/configuring particles: Boat, ChristmasSleigh, Farmhouse, Flame, Payable, Precipitation, Stars, Steed, TutorialTrail, Wall, Crown, InterfaceOverlay, and PayableTeleporter. None read computed particle output for gameplay or subscribed to particle events. Playground preset/recorder helpers also reference the plugin; they are not treated as gameplay evidence. The manager CIL confirms `LateUpdate` prepares and simulates particles, dispatches events, and copies results into the Unity particle system. This evidence supports the scoped bypass, not disabling arbitrary scripts by names such as “fire” or “weather.”

Validation on the desktop compatibility runtime:

- Eighteen visual regressions cover full-mode dispatch, initialization, lite clock advancement, newly subscribed manager callbacks, serialized events, local tracking and callback consumers, return to full mode, opaque depth fill, named cloud budgets, unknown/missing-field fallback and retained ice decoration.
- All 34 existing runtime regressions pass.
- Before cloud caps, full and lite modes each completed a fresh 2,400-frame starting sequence with identical scripted movement, zero logged exceptions, 31 audio starts and no missing clips. The final cloud-cap run also completed 2,400 frames with zero exceptions and 30 audio starts, with no missing clips; its controller dump confirms the cloud caps and empty fog/mist pools. No seed-for-seed comparison to the original Unity runtime is claimed.
- Before cloud-budget changes, a separate matching 1,000-frame capture comparison changed pixels only within the water region, rows 344–479 of the 640×480 screenshot. Every pixel above that region was identical. Lite and full captures were inspected visually. Cloud-budget changes intentionally change the sky/fog decoration as well.
- Native occlusion has 1,000 randomized command-list comparisons against execution of the exact same commands without clipping, covering alpha, additive, partial coverage, rotated lit/indexed sprites, multiple fills, foreground restoration and reflection ordering. All resulting pixels match; 323 cases perform less hidden raster work. Lists without an occluder retain their original work.
- An owned 329-command starting-scene capture, with only its reflection command replaced by an opaque bottom gradient, replayed at 0.507 ms/frame before clipping and 0.442 ms/frame after on the desktop, with identical output (`584018afd3743892` FNV-1a). The original reflection capture also has identical output before/after (`c7f7063d8b4d2f04`). This is a local renderer comparison rather than device FPS evidence.
- Desktop profiling showed lower particle and mesh work; these numbers do not establish Miyoo FPS. Device measurements must use the same scene/save/route, real elapsed frame time, and profiling disabled.

Local inspection captures contain owned game graphics and must not be packaged in public runtime releases.
